# Mini App Olimp

Источник дизайна: [Olympiad Tracker Mobile App](https://www.figma.com/design/Jms4ehBLLAgrGkFtm7G9js/Olympiad-Tracker-Mobile-App?node-id=19-2). Макеты просмотрены в Figma: светлый фон `#F8F9FB`, синие акценты, белые карточки, нижнее меню с четырьмя вкладками. Системную строку состояния телефона не рисуем внутри веб-страницы; безопасные отступы учитывают `safe-area-inset`.

## Запуск

Для первого запуска выполните [быстрый старт](../README.md#быстрый-старт): настройте окружение, создайте базу и импортируйте каталог. После этого:

```bash
pnpm dev
```

Клиент: <http://127.0.0.1:5173>, API: <http://127.0.0.1:3001>. Vite перенаправляет `/api/*` на API без изменения серверных маршрутов. Для раздельного запуска есть `pnpm dev:web` и `pnpm dev:api`.

`pnpm build` собирает сервер и клиент. `pnpm start` по-прежнему запускает только сервер. Готовый клиент находится в `apps/web/dist`; его нужно размещать отдельно на HTTPS с fallback маршрутов на `index.html`. Для предпросмотра сборки: `pnpm --filter @olimp/web preview`. Production-сборка не использует демонстрационный серверный вход.

## Страницы и работающие действия

| Маршрут | Возможности |
| --- | --- |
| `/catalog` | Переход к поиску, фильтры по предмету/классу/формату/уровню, сброс, сортировка, пагинация по 20 записей, сравнение двух олимпиад, добавление в план. На карточке — сколько дней осталось до следующего этапа (если дату можно посчитать). Фильтры сохраняются в URL. Возврат по ссылке, истории браузера или нижнему меню восстанавливает страницу и прокрутку в пределах текущего входа. |
| `/search` | Отдельный экран поиска: популярные запросы, локальная история последних восьми запросов, поиск с задержкой, результаты и подгрузка по 20 записей. |
| `/olympiads/:id` | Общий шаблон из Figma: заголовок и теги, описание, блок «Детали» (формат, проверенный дедлайн регистрации, этапы, дни до следующего этапа, организатор), кнопка отслеживания. Исходное расписание и льготы вузов раскрываются отдельно. Раздел «Особенности участия» убран. Раздел «Вузы с льготами» по макету «Олимпиада — Физтех»: карточка на каждый вуз из базы с льготой по олимпиаде (инициалы, льготы, условие ЕГЭ по нажатию), вуз-организатор первым, первые 5 и «Показать все». |
| `/plan` | Карточки по макету «Мой план»: плашка даты, название и формат, теги, строка срока и отметка срочности. Сохранённые олимпиады, фильтр по предметам, подтверждённые события на 90 дней, заметка, пауза отслеживания, удаление с подтверждением. Без подтверждённой даты показывается значок календаря и пояснение. Переключатель «Список / Календарь» (вид хранится в `?view=calendar`). Календарь по макету Figma «Мой план — Календарь»: месяц с переключением, дни с этапами отслеживаемых олимпиад (синий — регистрация, оранжевый — отбор/финал), выбор дня, список ближайших событий месяца с переходом к олимпиаде в плане; даты без года рассчитаны по сезону. |
| `/profile` | Изменение класса и формата, отдельное окно выбора предметов с подтверждением «Готово». |
| `/welcome`, `/login`, `/register` | Приветствие, вход через MAX, первичное заполнение профиля. |
| `/profile/edit` | Имя, регион (выбор из списка 89 регионов с подсказками при вводе), фото (JPG/PNG/WebP до 1 МБ), класс, предметы и формат. Сохранение профиля вместе с фото на сервере только по кнопке «Сохранить изменения». |
| `/profile/privacy` | Сведения об обработке данных. «Уведомления»: включение напоминаний бота, ссылка на бота и тестовое напоминание. Удаление аккаунта. Сброс учебных предпочтений в аккаунте. |
| `/profile/help` | Раскрывающиеся ответы FAQ, переход в поддержку при настроенном адресе. |
| `/profile/olympiad-faq` | «Вопросы по олимпиадам»: 35 вопросов и ответов из `data/faq/olympiad_faq_2026-27.csv` по разделам, у каждого ответа — официальные источники и дата проверки. Файл собирается в приложение при сборке; тот же файл использует Олимп. |
| `/olimp` | Чат с Олимпом по макету Figma 177:309: печать новых ответов, последовательное появление карточек, повтор при ошибке, источники и сохранение в план. Шапка использует `src/assets/olimp/logo.jpg`. Если в базе нет ответа, Олимп пишет «Сейчас поищу в интернете…» и сразу, без подтверждения, ищет на сайтах из списка ссылок; результат содержит ссылки (страница или PDF), дату и предупреждение, при сбое — кнопку «Повторить поиск». Ответы по базе вопросов показывают её официальные источники. Переписка остаётся при навигации; новый диалог или перезагрузка очищают её. |
| `/bot` | Совместимый переход на `/olimp`. |

Кнопка в карточке каталога: «Отслеживать» сохраняет олимпиаду в план; «Отслеживается» — нажатие ставит отслеживание на паузу, и кнопка становится «В плане»; «В плане» открывает эту запись в «Мой план» (`/plan?olympiad=<id>`), где отслеживание можно снова включить. Удаление — в окне записи с отдельным подтверждением.

## Настройки клиента

Образец — `apps/web/.env.example`. Для изменений создайте `apps/web/.env.local` и перезапустите Vite.

| Переменная | Назначение |
| --- | --- |
| `VITE_API_URL` | Публичный URL API. По умолчанию `/api`; при production-размещении нужен reverse proxy или явный URL API и разрешённый CORS origin. |
| `VITE_DATA_MODE` | `api` по умолчанию. `mock` включает явно отмеченную демоверсию без сервера. |
| `VITE_DEV_AUTH` | `false` отключает локальный `/auth/dev` вне MAX. Этот вход в любом случае разрешён клиентом только на Vite dev-сервере. |
| `VITE_SUPPORT_EMAIL` | Адрес почты поддержки; по умолчанию `olimp.max.support@gmail.com`. Кнопка открывает `mailto:` (в MAX через `WebApp.openLink`) и всегда показывает адрес с кнопкой копирования. |

В `VITE_*` нельзя хранить токены бота и другие секреты: значения попадают в сборку.

Чат использует серверные `DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL` в корневом `.env`. В mock-режиме чат явно отключён. Напоминания присылает MAX-бот (`apps/bot`, [BOT.md](BOT.md)); кнопка в сообщении открывает мини-приложение с `start_param`, который `src/lib/start-param.ts` превращает в маршрут. См. [ASSISTANT.md](ASSISTANT.md).

Для демонстрации без базы:

```bash
VITE_DATA_MODE=mock pnpm dev:web
```

Моки — снимок шести публичных записей API от 22.09.2026 в `src/lib/mock-details.json`. Форма ответов совпадает с контрактами. План демоверсии хранится отдельно от настоящего плана. При сбое API приложение показывает ошибку с повторной попыткой, а не подменяет данные демоверсией.

## Интеграция и границы

- MAX Bridge из официального CDN обёрнут в `src/lib/max.ts`. В обычном браузере системные методы не вызываются. В MAX `initData` отправляется на существующий `/auth/max`, JWT хранится только в памяти и обновляется после истечения. `initDataUnsafe` используется только для предварительного отображения имени, не для авторизации. Фото хранится в серверном профиле аккаунта; профиль обновляется при открытии приложения и возвращении в него.
- В краткую карточку API добавлено необязательное поле `organizers` из существующих данных; прежние ответы остаются совместимыми. Схема базы не менялась. Серверные данные находятся в TanStack Query. Zustand хранит только ID двух выбранных для сравнения олимпиад.
- Профиль синхронизируется через `/me` и `/me/profile`. В API нет удаления аккаунта и рассылки. Интерфейс не сообщает об успешном выполнении этих функций. Сброс предпочтений не удаляет серверный аккаунт или план.
- Без реального адреса поддержки сообщение никуда не отправляется. Удалённые ссылки открываются по явному нажатию, в MAX — через Bridge.
- Рейтинг источника не выдается за уровень РСОШ. Неизвестный год расписания не назначается автоматически. Статистика «Скоро» считает олимпиады с подтверждёнными событиями в 90-дневном окне. Статусы регистрации и завершения из макета не выдумываются.
- Реальный запуск внутри клиента MAX требует HTTPS-размещения и настройки бота; в этой реализации проверены браузер и локальный демонстрационный вход.

## Проверки

`pnpm typecheck`, `pnpm test`, `pnpm build` проверяют оба приложения. В тестах фронтенда проверяются соответствие моков реальным контрактам, сочетания фильтров, пагинация, повторное сохранение без потери заметки, пауза, удаление и повреждённое локальное хранилище.

Проверка браузером: страницы и нижняя навигация; сочетание фильтров при быстром переключении; пустой поиск; сравнение; добавление олимпиады в реальный локальный план; сохранение заметки и паузы после перезагрузки; редактирование класса/предметов и сохранение после перезагрузки; экспорт данных; сообщения о недоступном удалении аккаунта и уведомлениях; раскрытие FAQ. Все пять страниц проверены на ширине 320 px без горизонтального переполнения; визуальная проверка — на 375 px, ограничение ширины контейнера — на 1280 px. Тестовая запись плана удалена, профиль возвращён в исходное состояние.

Авторизация, создание профиля, миграция прежних локальных настроек и ограничения: [AUTH.md](AUTH.md).
