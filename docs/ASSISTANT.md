# Чат «Олимп»

Экран повторяет [макет Figma «Олимп»](https://www.figma.com/design/Jms4ehBLLAgrGkFtm7G9js/Olympiad-Tracker-Mobile-App?node-id=177-309): шапка с логотипом из `apps/web/src/assets/olimp/logo.jpg`, светлые ответы, синие сообщения пользователя, карточки олимпиад, поле ввода и нижняя навигация. Системная строка телефона не рисуется.

## Запуск

В корневом `.env` нужны `DEEPSEEK_API_KEY` и при необходимости `DEEPSEEK_MODEL` (по умолчанию `deepseek-flash`). Для поиска в интернете отдельный ключ не нужен. Файл исключён из Git. В production передавайте переменные через секреты окружения сервера. В браузере ключа нет. После изменения `.env` перезапустите API.

Обычный `pnpm dev` запускает приложение. Откройте <http://127.0.0.1:5173/olimp>. Вне MAX нужен локальный демонстрационный вход, в MAX — проверенные стартовые данные. В `VITE_DATA_MODE=mock` чат отключён, ответы не имитируются.

DeepSeek интегрирован через официальный [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) с [JSON Output](https://api-docs.deepseek.com/guides/json_mode/), без дополнительных SDK. Адрес API фиксирован, reasoning выключен, ответы и входные параметры проверяются Zod.

## Как получается ответ

1. Сервер проверяет JWT и существование пользователя. DeepSeek получает текст вопроса и ограниченную историю; определяет область запроса и параметры поиска.
2. Сервер выполняет только разрешённые чтения: каталог по предметам, классу, формату, названию и вузу; карточки; план текущего пользователя; подтверждённые ближайшие этапы; базу вопросов `data/faq`; льготы вузов. Если подтверждённых будущих этапов нет, сервер выбирает записи с текстом расписания или исходными датами этапов, сохраняя фильтры названия, предмета, класса и формата. Произвольного SQL и доступа к файлам у модели нет. Внешние сайты открываются только на втором шаге, если база не ответила (см. ниже).
3. Второй запрос к DeepSeek формирует ответ из найденных данных. Карточки и ссылки берутся сервером из базы по проверенным ID. Выдуманные ID отклоняются. Посторонние вопросы и попытки сменить роль получают фиксированный ответ о назначении Олимпа.

Это ограниченный поиск с генерацией по найденным записям, без отдельной векторной базы. Ответы могут ошибаться: инструкции и проверка структуры не дают математической гарантии отсутствия галлюцинаций. Источники доступны в карточках. Модель получает текст расписания `calendarText`, статус, уровень, профиль и статус уровня из CSV. При запросах ближайших дат отсутствие подтверждённых этапов не прерывает ответ: модель получает `scheduleMode=source_text`, исходный календарь и `sourceStages` с названиями и датами этапов. Она показывает имеющиеся сроки, явно отделяя их от подтверждённых ближайших событий. Данные читаются из PostgreSQL при каждом запросе, поэтому повторный импорт доступен сразу, без перезапуска помощника. Текстовые сроки можно цитировать без добавления года; расчёт ближайших событий разрешён только по `verifiedStages` (`verified_import/verified`). Неподтверждённые или утратившие подтверждение даты не попадают в `verifiedStages`. Отсутствие даты не означает закрытую регистрацию. Даже подтверждённый этап оценивается относительно текущей московской даты.

## Что умеет интерфейс

- Новые ответы постепенно печатаются, после текста карточки плавно появляются по очереди. Завершённые сообщения не проигрывают анимацию заново при навигации. Учитывается системное уменьшение движения.
- Отправка кнопкой или Enter; Shift+Enter добавляет строку. Черновик остаётся при переходе между разделами.
- Карточки из ответа открывают настоящие страницы; возврат ведёт в тот же диалог.
- Карточка олимпиады в чате по макету: название, «организатор · ближайшая дата» и «Подробнее ›». Сохранение в план — кнопкой «Отслеживать» на странице олимпиады; модель не выполняет запись и не сообщает о сохранении сама.
- Ожидание ответа, запрет двойной отправки, понятные ошибки и повтор не создают дубликат пользовательской реплики.
- «Новый диалог» очищает переписку, отменяет активный запрос и сохраняет личный план.
- Поле ввода и вкладки остаются в видимой области при изменении высоты экрана; предусмотрены safe-area, прокрутка истории и уменьшение анимации.

## Сленг

Школьники пишут «матеша», «инфа», «общага», «физра», «русич», «олимпы», «всош», «ЗЭ», «вышка», «бауманка», «бвишка», «сотка». Перед вызовом модели сервер раскрывает такие слова по словарю `apps/api/src/features/assistant/slang.ts`: модель получает исходное сообщение, `normalizedMessage` и `glossary` с расшифровками. Двусмысленные слова раскрываются по контексту: «олимпиады по общаге» — обществознание, «есть ли общага в МФТИ» — общежитие (только пояснение в глоссарии); «по инфе» — информатика, «нет инфы о сроках» — информация. Если модель всё же не выбрала предмет или сочла короткий запрос вроде «олимпы по матеше 9 класс» посторонним, сервер сам подставляет предмет из словаря и выполняет поиск. Новые слова добавляются строкой в словарь; тесты — `tests/assistant.test.ts`.

## База вопросов и вузы

Общие вопросы («Можно ли заявить БВИ в нескольких вузах?», «Как работает 100 баллов?») получают `intent=question`. Сервер подбирает до шести записей из `data/faq/olympiad_faq_2026-27.csv` — того же файла, что показан в профиле в разделе «Вопросы по олимпиадам», — и передаёт их модели как проверенные факты. Под ответом показываются официальные источники использованных записей (`kind=faq`). Вузы из справочника льгот распознаются по названию и сленгу: вопрос о вузе получает его льготы из базы, а подбор «какие олимпиады дают БВИ в МИФИ» фильтрует каталог по этому вузу.

## Поиск в интернете без согласия и без поисковика

Если ответа нет ни в каталоге, ни в базе вопросов, ни в льготах вузов, Олимп пишет, чего не хватает, и добавляет «Сейчас поищу в интернете…». Приложение сразу, без кнопок «Да/Нет», отправляет подписанный билет в `/assistant/web-search`, показывает «Ищет в интернете…», а затем — ответ со ссылками и предупреждением. Прямая просьба «поищи в интернете» запускает то же самое. Если поиск прервался, у сообщения есть кнопка «Повторить поиск».

Сторонний поисковик (прежде Serper) удалён. Сервер открывает только известные адреса:

1. страницу олимпиады на olimpiada.ru и сайт организатора из контактов карточки (если вопрос об олимпиаде каталога);
2. список `data/assistant/university_links_descriptions.csv`: официальные сайты и правила приёма 23 вузов, РСОШ, Минпросвещения, olimpiada.ru, Учёба.ру, рейтинги RAEX и Forbes, Табитуриент, Вузопедия. У каждой ссылки есть описание — по нему DeepSeek выбирает, куда идти.

DeepSeek выбирает до пяти адресов, сервер читает до трёх (остальные — если первые недоступны). HTML и PDF (правила приёма обычно в PDF) превращаются в текст; из длинных документов модель получает начало и фрагменты со словами вопроса. Если ответа на прочитанных страницах нет, но там есть подходящая ссылка («Правила приёма», «Особые права»), сервер один раз переходит по ней. Ответ содержит только факты с прочитанных страниц, номера источников и реальные ссылки. Если сайты недоступны или ответа нет, бот честно говорит об этом.

Список ссылок меняется правкой CSV (столбцы «Описание» и «Ссылка»), после чего API нужно перезапустить. Метки `utm_*` из ссылок отбрасываются. Произвольные URL из ответа модели не открываются: только из списка, карточки или ссылок на уже прочитанных страницах. Загрузка ограничена размером (HTML — 800 КБ, PDF — 15 МБ), временем (15 секунд на документ) и числом переадресаций; локальные и частные адреса запрещены, DNS проверяется и соединение привязывается к проверенному адресу. Тексты сайтов считаются недоверенными данными.

## Данные и ограничения

Переписка хранится только в памяти открытого приложения. Последние максимум 10 реплик, до 12 000 символов вместе с вопросом, передаются серверу. При перезагрузке история очищается. Сервер не пишет историю в БД и не логирует сообщения или ответы провайдера. DeepSeek получает вопрос, историю и нужные сведения каталога; при запросе своего плана — данные сохранённых олимпиад без заметок и идентификатора пользователя. Это не является обещанием о хранении данных самим провайдером. В интерфейсе есть ссылка на пояснение обработки данных.

Один запрос содержит до 2 000 символов; не более 10 запросов в минуту на пользователя, один активный запрос на пользователя и до 8 на процесс сервера. Ограничитель локален процессу: перед масштабированием на несколько серверов нужен общий rate-limit store. Каждый из двух вызовов DeepSeek ограничен 25 секундами; общий серверный срок — 55 секунд. Автоматических повторов платных запросов нет.

Для поиска в интернете действует отдельный лимит 6 запросов в минуту; ограничение одновременных запросов общее с чатом. Чтение документа ограничено 15 секундами, каждый вызов DeepSeek — 25 секундами (при поиске их до трёх). Общий серверный срок — 100 секунд, клиентский — 110 секунд. При ошибке пользователь может повторить тот же поиск, пока билет не истёк (15 минут).

Для скорости выдача ограничена: до 6 записей на поисковый запрос, до 12 изучаемых карточек и до 5 карточек в ответе. Это не полный обзор всех олимпиад. Регион, курс студента и уровень РСОШ не представлены надёжными отдельными полями; ассистент не должен их додумывать. Рассылка сообщений в MAX, запись в план текстовой командой, регистрация на олимпиаду и обновление источников не реализованы.

## Проверка

`pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm build`. Тесты не используют реальный ключ и не расходуют API: проверяют границы входа, источники/даты, ошибки провайдера, авторизацию и изоляцию плана. Живую интеграцию проверяют отдельно через локальное приложение.

## Профиль и личный план

Каждый запрос чата получает свежие класс, названия интересующих предметов, настройки онлайн/очно и план из базы по ID авторизованного пользователя. Оба этапа ответа DeepSeek получают этот контекст. Фото, имя, регион и идентификатор MAX не передаются. Для подбора недостающие критерии дополняются профилем; явные критерии важнее, просьба искать без предпочтений отключает подстановку. Данные профиля не ограничивают просмотр конкретной олимпиады или собственного плана. В контексте плана передаются первые 100 записей с названиями и статусом отслеживания, общее число и признак сокращения. Личные заметки из плана DeepSeek не получает никогда — так обещает экран «Данные и конфиденциальность», и это проверяет интеграционный тест. Изменять профиль и план ассистент не умеет. Поиск в интернете не получает объект контекста профиля.
