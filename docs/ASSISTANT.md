# Чат «Олимп»

Экран повторяет [макет Figma «Олимп»](https://www.figma.com/design/Jms4ehBLLAgrGkFtm7G9js/Olympiad-Tracker-Mobile-App?node-id=177-309): шапка с логотипом из `apps/web/src/assets/olimp/logo.jpg`, светлые ответы, синие сообщения пользователя, карточки олимпиад, поле ввода и нижняя навигация. Системная строка телефона не рисуется.

## Запуск

В корневом `.env` нужны `DEEPSEEK_API_KEY`, серверный `SERPER_API_KEY` для поиска в интернете и при необходимости `DEEPSEEK_MODEL` (по умолчанию `deepseek-flash`). Файл исключён из Git. В production передавайте переменные через секреты окружения сервера. В браузере ключа нет. После изменения `.env` перезапустите API.

Обычный `pnpm dev` запускает приложение. Откройте <http://127.0.0.1:5173/olimp>. Вне MAX нужен локальный демонстрационный вход, в MAX — проверенные стартовые данные. В `VITE_DATA_MODE=mock` чат отключён, ответы не имитируются.

DeepSeek интегрирован через официальный [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) с [JSON Output](https://api-docs.deepseek.com/guides/json_mode/), без дополнительных SDK. Адрес API фиксирован, reasoning выключен, ответы и входные параметры проверяются Zod.

## Как получается ответ

1. Сервер проверяет JWT и существование пользователя. DeepSeek получает текст вопроса и ограниченную историю; определяет область запроса и параметры поиска.
2. Сервер выполняет только разрешённые чтения: каталог по предметам, классу, формату и названию; карточки; план текущего пользователя; подтверждённые ближайшие этапы. Произвольного SQL и доступа к файлам у модели нет. В обычном ответе внешние сайты не открываются.
3. Второй запрос к DeepSeek формирует ответ из найденных данных. Карточки и ссылки берутся сервером из базы по проверенным ID. Выдуманные ID отклоняются. Посторонние вопросы и попытки сменить роль получают фиксированный ответ о назначении Олимпа.

Это ограниченный поиск с генерацией по найденным записям, без отдельной векторной базы. Ответы могут ошибаться: инструкции и проверка структуры не дают математической гарантии отсутствия галлюцинаций. Источники доступны в карточках. Модель получает текст расписания `calendarText`, статус, уровень, профиль и статус уровня из CSV. Текстовые сроки можно цитировать без добавления года; расчёт ближайших событий разрешён только по `verifiedStages` (`verified_import/verified`). Неподтверждённые или утратившие подтверждение даты не попадают в `verifiedStages`. Отсутствие даты не означает закрытую регистрацию. Даже подтверждённый этап оценивается относительно текущей московской даты.

## Что умеет интерфейс

- Новые ответы постепенно печатаются, после текста карточки плавно появляются по очереди. Завершённые сообщения не проигрывают анимацию заново при навигации. Учитывается системное уменьшение движения.
- Отправка кнопкой или Enter; Shift+Enter добавляет строку. Черновик остаётся при переходе между разделами.
- Карточки из ответа открывают настоящие страницы; возврат ведёт в тот же диалог.
- «В план» использует существующее авторизованное сохранение и обновляет общий кэш плана. Модель не выполняет запись и не сообщает о сохранении сама.
- Ожидание ответа, запрет двойной отправки, понятные ошибки и повтор не создают дубликат пользовательской реплики.
- «Новый диалог» очищает переписку, отменяет активный запрос и сохраняет личный план.
- Поле ввода и вкладки остаются в видимой области при изменении высоты экрана; предусмотрены safe-area, прокрутка истории и уменьшение анимации.

## Проверка внешних источников по согласию

Если для вопроса о найденной олимпиаде не хватает данных базы, Олимп предлагает проверить сайты. В компактном предложении пользователь видит самостоятельный вопрос по контексту и кнопки «Да» / «Нет». Нормализованный вопрос и выбранные ID формируются по ограниченной истории разговора: просьба «поищи больше информации» не используется как буквальный поисковый запрос. Если объект неоднозначен, бот уточняет название. При прямой просьбе поискать в интернете возвращается только предложение, без второго вызова модели, пересказа базы и повторной карточки. В обычном уточнении ранее показанные карточки не дублируются при нехватке сведений. Короткое однозначное «Да» в ответ на последнее предложение также подтверждает поиск. До согласия сервер не обращается к Serper и не загружает страницы.

Сервер выполняет поиск через [Serper](https://serper.dev): `POST https://google.serper.dev/search`, ключ в заголовке `X-API-KEY`, русская выдача. На одну выбранную олимпиаду отправляется один запрос из короткого названия и ключевых слов нормализованного вопроса по контексту (до трёх запросов по пять результатов). Поиск не ограничен ссылками из каталога. DeepSeek выбирает до трёх релевантных результатов с приоритетом организатора; сервер пытается прочитать их HTML. Произвольные придуманные ссылки не открываются.

Если страница требует JavaScript, недоступна или является PDF, можно использовать только краткую выдержку из выдачи Serper. Такой источник отдельно помечается в интерфейсе как «выдержка из поиска» и не выдаётся за прочитанный документ. Если подходящих результатов или точного ответа нет, бот сообщает об этом. При ошибке Serper старый обход сайтов автоматически не включается. Без `SERPER_API_KEY` обычный чат по базе работает, интернет-поиск возвращает понятную ошибку.

Ответ содержит реальные ссылки, дату проверки и отдельное предупреждение самостоятельно проверить актуальность и условия у организатора. Такие сведения не становятся подтверждёнными этапами в базе и не изменяют план. Короткое название олимпиады и ключевые слова нормализованного вопроса передаются Serper как поисковый запрос (без истории, ID пользователя и личного плана). Вопрос, результаты поиска и текст страниц передаются DeepSeek; самим найденным сайтам сервер отправляет обычные GET-запросы без переписки, cookies и личных данных пользователя.

Подтверждение связано с вопросом, выбранными ID и текущим пользователем подписанным токеном на 15 минут. Произвольный URL передать нельзя. Загрузка ограничена размером, временем и числом переходов; локальные и частные адреса запрещены, DNS проверяется и соединение привязывается к проверенному адресу. Тексты сайтов считаются недоверенными данными.

## Данные и ограничения

Переписка хранится только в памяти открытого приложения. Последние максимум 10 реплик, до 12 000 символов вместе с вопросом, передаются серверу. При перезагрузке история очищается. Сервер не пишет историю в БД и не логирует сообщения или ответы провайдера. DeepSeek получает вопрос, историю и нужные сведения каталога; при запросе своего плана — данные сохранённых олимпиад без заметок и идентификатора пользователя. Это не является обещанием о хранении данных самим провайдером. В интерфейсе есть ссылка на пояснение обработки данных.

Один запрос содержит до 2 000 символов; не более 10 запросов в минуту на пользователя, один активный запрос на пользователя и до 8 на процесс сервера. Ограничитель локален процессу: перед масштабированием на несколько серверов нужен общий rate-limit store. Каждый из двух вызовов DeepSeek ограничен 25 секундами; общий серверный срок — 55 секунд. Автоматических повторов платных запросов нет.

Для проверки сайтов действует отдельный лимит 3 запроса в минуту; ограничение одновременных запросов общее с чатом. Serper ограничен 12 секундами, чтение страницы — 8 секундами, каждый вызов DeepSeek — 25 секундами. Общий серверный срок — 70 секунд, клиентский — 80 секунд. Ключ Serper передаётся только фиксированному адресу провайдера, перенаправления запрещены; ошибки провайдера не раскрывают ключ и поисковый запрос. При ошибке пользователь может явно повторить тот же поиск, пока подтверждение не истекло.

Для скорости выдача ограничена: до 6 записей на поисковый запрос, до 12 изучаемых карточек и до 5 карточек в ответе. Это не полный обзор всех олимпиад. Регион, курс студента и уровень РСОШ не представлены надёжными отдельными полями; ассистент не должен их додумывать. Рассылка сообщений в MAX, запись в план текстовой командой, регистрация на олимпиаду и обновление источников не реализованы.

## Проверка

`pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm build`. Тесты не используют реальный ключ и не расходуют API: проверяют границы входа, источники/даты, ошибки провайдера, авторизацию и изоляцию плана. Живую интеграцию проверяют отдельно через локальное приложение.
