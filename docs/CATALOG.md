# Каталог и обновление данных

Исходная выгрузка находится в `data/catalog/olimpiady.csv`. Команды выполняются из корня репозитория.

## Импорт и обновление

```bash
pnpm db:audit
pnpm db:import
# Частичная выгрузка (поддерживаются исходные 19 и новые 28 столбцов):
pnpm db:import /absolute/path/olimpiady.csv
# Полная замена состава каталога произвольным файлом:
pnpm db:import /absolute/path/olimp.csv --replace-catalog
```

Импорт сначала проверяет весь файл, затем выполняется в одной транзакции. Неверная строка отменяет импорт с сообщением об ошибке. Ключ записи — ID страницы olimpiada.ru. Исходные поля сохраняются в `rawSource` без потерь, а нормализованные значения используются для фильтров.

`pnpm db:import` без пути полностью обновляет состав каталога из комплектного CSV. Отсутствующие записи получают `inCatalog=false`: они скрыты из каталога и его фильтров, но остаются доступны по прямой ссылке и в сохранённых планах с заметками. При обновлении старой базы это 131 запись. Импорт с явным путём по умолчанию считается частичным и не скрывает отсутствующие записи; для полной замены передайте `--replace-catalog`. Повторное появление ID возвращает запись в каталог. Отчёт содержит `missingFromFile` и `hiddenFromCatalog`. Предыдущие импорты зарегистрированы в `import_runs`.

После получения изменений сначала выполните `pnpm db:migrate`, затем `pnpm db:import` и пересоберите приложение. Для Docker порядок приведён в [docs/DEPLOYMENT.md](DEPLOYMENT.md). Один Git push не обновляет PostgreSQL на сервере.

Отчёты создаются локально в `data/source-audit.json` и `data/import-report.json` и не включаются в Git.

### Перенос базы

Для новой установки используйте `db:migrate` и `db:import`. Локальные SQL-снимки и резервные копии не публикуются в Git; миграции создают актуальную схему, исходный CSV восстанавливает каталог. Перенос существующих пользователей и планов выполняется отдельно через защищённую резервную копию PostgreSQL.

## Справочник: уровни, этапы, льготы

```bash
pnpm data:check     # проверить data/reference без базы → data/reference-report.json
pnpm db:reference   # загрузить только справочник
```

`pnpm db:import` загружает справочник в той же транзакции, что и каталог (`--skip-reference` — без него). Олимпиада-«серия» («Олимпиада РАНХиГС») связывает источники без разделения по предметам с предметными карточками каталога; этапы и льготы серии применяются ко всем её карточкам, а уровень — по профилю каждой. Правила и порядок обновления: [data/reference/README.md](../data/reference/README.md).

## Подтверждённые этапы

Подготовьте JSON по [инструкции](DATA_MODEL.md#проверенные-даты) после проверки официального расписания и выполните:

```bash
pnpm db:stages /absolute/path/verified-stages.json
```

Готовый файл сезона 2026/27 загружается командой `pnpm db:verified` (`data/verified/stages-2026-27.json`, 174 этапа на 71 карточке); ссылки и выдержки из источников — в `data/verified/sources-2026-27.csv`. Запускайте её после `pnpm db:import` и повторно — только после новой сверки.

Команда сохраняет результат проверки, **сама сайт не проверяет**. Импортировать проверенные этапы может оператор с доступом к базе; публичного endpoint для присвоения датам статуса «проверено» нет. Тестовые даты находятся только в тестах и не попадают в рабочую базу.
