# Публичный запуск Olimp в MAX

Код находится в ветке [Ilya](https://github.com/Gleb-hack/olimpmax/tree/Ilya). Для работы пользователей нужен постоянно включённый сервер с PostgreSQL и HTTPS. GitHub хранит исходники; загрузка ветки сама по себе приложение не публикует.

В этой инструкции один VPS обслуживает интерфейс, API и базу. Docker Compose запускает PostgreSQL, применяет миграции, запускает API и Caddy. Caddy выдаёт HTTPS-сертификат и направляет `/api/*` в API. Данные и сертификаты сохраняются в отдельных Docker volumes.

## 1. Сервер и домен

Подойдёт VPS с Ubuntu 24.04 LTS. Для небольшого пилота ориентир — 2 vCPU, 4 ГБ RAM и 20 ГБ SSD; фактическую нагрузку нужно измерять. Нужны SSH-доступ и домен, например `olimp.example.ru`.

1. Создайте DNS-запись A домена на публичный IPv4 сервера. Если создаёте AAAA, IPv6 тоже должен вести на этот сервер.
2. Разрешите входящие TCP 80 и 443 в firewall хостинга. SSH оставьте доступным для администрирования. Порты 3001 и 5432 открывать не требуется.
3. Установите Docker Engine и Compose plugin по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Проверьте `docker version` и `docker compose version`.
4. Установите Git: `sudo apt-get update && sudo apt-get install -y git openssl`.

Команды ниже выполняются на сервере. Если Docker требует права администратора, добавляйте `sudo` перед `docker`.

Не запускайте конфигурацию поверх существующего сайта, который уже занимает порты 80/443: используйте отдельный VPS или согласуйте маршрутизацию с администратором этого сервера.

## 2. Скачать ветку и задать настройки

```bash
git clone --branch Ilya --single-branch https://github.com/Gleb-hack/olimpmax.git
cd olimpmax
cp .env.production.example .env.production
chmod 600 .env.production
openssl rand -hex 32
openssl rand -hex 32
nano .env.production
```

Заполните файл:

| Переменная | Что указать |
| --- | --- |
| `APP_DOMAIN` | Ваш домен, без `https://` и завершающего слеша |
| `POSTGRES_PASSWORD` | Первый сгенерированный набор из 64 шестнадцатеричных символов |
| `JWT_SECRET` | Второй, отдельный набор |
| `MAX_BOT_TOKEN` | Токен того бота MAX, через который пользователь открывает приложение |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek, если нужен чат «Олимп» |
| `SERPER_API_KEY` | Ключ Serper, если нужен поиск из чата |
| `DEEPSEEK_MODEL` | По умолчанию `deepseek-flash` |

Пароль PostgreSQL здесь используется внутри URL: используйте предложенный hex-формат. Не меняйте его после первого запуска без отдельной смены пароля в самой PostgreSQL.

`.env.production` исключён из Git и Docker build context. Токен передаётся только серверному контейнеру при запуске. Не помещайте его в `VITE_*`, исходники или настройки публичного сайта. Для регистрации, профиля и плана ключи DeepSeek/Serper не нужны.

## 3. Запустить приложение и загрузить каталог

```bash
docker compose --env-file .env.production -f compose.production.yaml up -d --build
docker compose --env-file .env.production -f compose.production.yaml run --rm --no-deps api pnpm db:import
docker compose --env-file .env.production -f compose.production.yaml ps -a
```

Первый запуск скачивает образы и собирает приложение. Сервис `migrate` должен закончиться с кодом 0; `postgres` и `api` — перейти в healthy, `web` — работать. Импорт загружает 771 олимпиаду и 35 предметов из CSV. SQL-дамп с локального компьютера не требуется.

Проверьте со своего компьютера, заменив домен:

```bash
curl --fail https://olimp.example.ru/api/health
```

Ожидается `{"status":"ok"}`. Откройте `https://olimp.example.ru/welcome`: должен появиться экран приветствия. Caddy автоматически получает сертификат, если DNS настроен и порты доступны. Требования описаны в [документации Caddy](https://caddyserver.com/docs/automatic-https).

## 4. Подключить Mini App к боту MAX

В кабинете [MAX для партнёров](https://business.max.ru) откройте «Чат-боты», выберите своего бота → меню «⋮» → «Настройки». Укажите публичный HTTPS URL приложения, например `https://olimp.example.ru`, настройте кнопку запуска и сохраните.

Официальный порядок и требования кабинета: [подключение Mini App](https://dev.max.ru/docs/webapps/introduction). Если бот ещё не подключён к кабинету, сначала завершите доступную для вашего аккаунта регистрацию/подключение бота.

Открывайте приложение кнопкой в этом боте либо ссылкой `https://max.ru/<botName>?startapp`, где `<botName>` — реальный username бота.

**Вход рассчитан на открытие внутри MAX.** Простое открытие домена в обычном браузере покажет интерфейс, но не предоставит подтверждённую личность MAX. В production демонстрационный вход выключен.

## 5. Как работают регистрация и вход

1. MAX передаёт приложению подписанные стартовые данные.
2. Сервер проверяет подпись токеном бота и создаёт либо находит пользователя по его MAX ID.
3. Новый пользователь заполняет имя, класс/курс, регион, предметы и форматы на экране регистрации.
4. При повторном входе тот же MAX ID получает прежний профиль и личный план, в том числе с другого устройства.

Отдельного пароля в Olimp нет. Пользователи хранятся в `user_profiles`, их предметы — в `user_subjects`, связь пользователя с выбранной олимпиадой — в `plan_items`. Проверка подписи выполняется по [официальному алгоритму MAX](https://dev.max.ru/docs/webapps/validation).

Токен должен принадлежать именно боту запуска. Неподходящий токен или устаревшие данные запуска приведут к отказу во входе. При сообщении об истёкшей сессии закройте и снова откройте Mini App в MAX.

## 6. Проверка после подключения

- Откройте Mini App в MAX, зарегистрируйтесь и сохраните олимпиаду в план.
- Закройте Mini App, откройте снова и проверьте профиль и план.
- Измените профиль, выйдите и войдите повторно.
- Откройте приложение с другого MAX-аккаунта: чужой план и профиль не должны отображаться.
- Перезапустите контейнеры и убедитесь, что данные сохранились.
- Если подключён DeepSeek, проверьте чат; при наличии Serper — согласованный поиск в интернете.

Локальные проверки и тесты не заменяют этот запуск в настоящем MAX. Рассылка напоминаний и удаление серверного аккаунта пока не реализованы. Фотография профиля хранится на устройстве; учебные предпочтения и план — на сервере.

## 7. Обновления и резервные копии

Перед обновлением сделайте резервную копию:

```bash
mkdir -p backups
chmod 700 backups
umask 077
docker compose --env-file .env.production -f compose.production.yaml exec -T postgres pg_dump -U olimp -d olimp -Fc > "backups/olimp-$(date +%Y%m%d-%H%M%S).dump"
```

Копируйте резервные копии на отдельное защищённое хранилище и периодически проверяйте восстановление в отдельной базе. Папка `backups/` исключена из Git и образов.

Обновление:

```bash
git pull --ff-only origin Ilya
docker compose --env-file .env.production -f compose.production.yaml build
docker compose --env-file .env.production -f compose.production.yaml stop api web
docker compose --env-file .env.production -f compose.production.yaml run --rm migrate
docker compose --env-file .env.production -f compose.production.yaml up -d
```

Продолжайте запуск только после успешной миграции. На время обновления приложение недоступно. Если изменился CSV, повторите команду импорта из шага 3: она сохраняет существующие личные планы. Не используйте `down -v` для обновлений — этот флаг удаляет постоянные volumes, включая базу.

## 8. Если что-то не работает

```bash
docker compose --env-file .env.production -f compose.production.yaml logs --tail=100 api migrate web
```

| Симптом | Что проверить |
| --- | --- |
| Нет HTTPS / сайт не открывается | DNS, IP, доступность 80/443, отсутствие другого веб-сервера на этих портах |
| 502/503 или нет каталога | Состояние API/базы, результат миграции и импорта |
| «Откройте Olimp в MAX» | Приложение запущено из бота, а не из обычного браузера |
| «Недействительные данные MAX» | Токен соответствует боту, время сервера правильное; закройте и снова откройте Mini App |
| Чат не работает, но каталог доступен | Серверный ключ DeepSeek и доступ к его API |
| Изменили настройки, но ничего не изменилось | Повторите `up -d` для пересоздания контейнеров с новым окружением |

Не публикуйте `.env.production`, полные стартовые данные MAX или заголовок Authorization при обращении за помощью.

В Compose API и PostgreSQL не публикуют порты наружу. `TRUST_PROXY_HOPS=1` разрешает API учитывать адрес клиента только от непосредственного прокси в частной сети или loopback; это нужно для ограничений частоты запросов. При другой сетевой схеме настройку нужно пересмотреть.

Старый прототип из `main` сохранён в этой ветке в `legacy/main-prototype/` только как архив. Его сценарий публикации не запускается; текущий стек использует `compose.production.yaml`.
