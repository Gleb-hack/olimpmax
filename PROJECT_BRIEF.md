# Olimp — Mini App для MAX

Этот файл — единый контекст проекта для новых чатов и участников команды. Перед началом работы прочитай его целиком. Если новое решение противоречит этому документу, сначала объясни причину и предложи безопасный вариант миграции.

## Идея продукта

**Olimp** — мини-приложение внутри мессенджера MAX, которое помогает школьникам и студентам находить олимпиады, следить за регистрациями и сроками, а также получать помощь через бот.

Основные разделы из дизайн-концепта:

- **Олимп** — чат-помощник: подбор олимпиад из каталога, сведения об участии и подтверждённые дедлайны.
- **Каталог** — поиск, фильтры, карточки олимпиад, добавление в план и сравнение.
- **План** — сохранённые олимпиады, ближайшие регистрации и этапы.
- **Профиль** — класс/курс, предметы, регион и настройки.

Цель хакатона — показать цельный рабочий путь: пользователь выбирает олимпиаду в каталоге, добавляет её в личный план и получает напоминание от бота о дедлайне.

## Выбранный стек

| Зона | Технологии | Зачем |
| --- | --- | --- |
| Mini App | React + TypeScript + Vite | Быстрый SPA-клиент для WebView MAX. |
| UI | `@maxhub/max-ui` + собственные CSS-дизайн-токены | Базовая совместимость с интерфейсом MAX и свобода повторить концепт. |
| Навигация | React Router | Четыре вкладки и детальные экраны. |
| Работа с API | TanStack Query | Кэширование, загрузка, ошибки и обновление данных без ручной логики. |
| Локальное UI-состояние | Zustand | Например: открытые фильтры, выбранные для сравнения олимпиады. Не хранить здесь серверные данные. |
| API | Node.js + TypeScript + Fastify | Один язык с фронтендом и ботом, быстрый и простой сервер. |
| Бот | `@maxhub/max-bot-api` | Официальная JavaScript/TypeScript-библиотека MAX. |
| База | PostgreSQL + Drizzle ORM | Реляционные данные, типизированные миграции, фильтрация и дедлайны. |
| Контракты API | Zod | Один источник типов и валидации для фронтенда и сервера. |
| Репозиторий | `pnpm workspace` | Общие пакеты без копирования кода и без сложности микросервисов. |

**Не используем:** Flutter/React Native, Next.js, микрофронтенды, Kubernetes и отдельный Python-бэкенд. Для Mini App они усложнят интеграцию и не дадут ценности на хакатоне.

## Целевая структура репозитория

```text
apps/
  web/                 # React Mini App
  api/                 # Fastify API, авторизация, PostgreSQL
  bot/                 # сценарии и уведомления MAX
packages/
  contracts/           # Zod-схемы, типы DTO, общие константы
  ui/                  # нижняя навигация, карточки, дизайн-токены
data/
  olimpiady.csv        # исходный импортный набор, не источник правды в рантайме
```

Пока в корне проекта находится `olimpiady.csv`: это исходный набор данных для первичного импорта. В данных есть поле источника и URL. Перед показом дат пользователю проверять актуальность по официальному источнику; CSV нельзя считать автоматически достоверным календарём.

## Главные сущности

```text
Olympiad       # название, предмет, классы/курс, формат, организатор, описание, ссылка на источник
OlympiadStage  # регистрация / отборочный / заключительный этап, beginsAt, endsAt, статус
UserProfile    # maxUserId, имя, класс/курс, регион, интересующие предметы
PlanItem       # пользователь + олимпиада + отслеживание + пользовательская заметка
Reminder       # PlanItem + момент отправки + статус доставки
```

Идентификаторы пользователя берём из MAX, а не из самодельной регистрации.

## Интеграция с MAX: обязательные правила

- Mini App — веб-приложение, привязанное к чат-боту MAX; для размещения нужен публичный URL по HTTPS.
- На клиенте подключить MAX Bridge (`window.WebApp`) через тонкую обёртку `src/lib/max.ts`; в браузерной разработке обёртка должна иметь mock-режим.
- Не доверять `initData` на клиенте. Клиент отправляет его в `POST /auth/max`, сервер проверяет HMAC-подпись токеном бота, затем выдаёт короткоживущую сессию/JWT.
- Токен бота хранить только в переменных окружения сервера. Никогда не класть его в Vite-переменные `VITE_*`, клиентский код или Git.
- Переход к официальному сайту олимпиады открывать только после явного клика пользователя через возможности MAX Bridge.

Официальные материалы: [подключение Mini App](https://dev.max.ru/docs/webapps/introduction), [MAX Bridge](https://dev.max.ru/docs/webapps/bridge), [валидация стартовых данных](https://dev.max.ru/docs/webapps/validation), [MAX UI](https://dev.max.ru/ui).

## Как работать вдвоём

1. Сначала меняем или согласовываем схему в `packages/contracts`; фронтенд и API не изобретают разные поля одних сущностей.
2. Каждый делает независимую feature-папку: `features/catalog`, `features/plan`, `features/profile`, `features/assistant`.
3. Общие компоненты добавляются в `packages/ui`, а не копируются между вкладками.
4. Ветки называем `feature/catalog-filters`, `feature/plan`, `feature/api-import` и т. п. Каждый pull request — одна задача.
5. Фронтенд разрабатывается на mock-данных, но их форма должна соответствовать Zod-контрактам. После готовности API мок заменяется без переделки экранов.

## MVP и границы

### В MVP обязательно

- каталог с поиском и фильтрами по предмету, классу/курсу и формату;
- карточка олимпиады с источником, датами и ссылкой;
- добавление/удаление из личного плана;
- экран плана с ближайшими дедлайнами;
- бот открывает Mini App и присылает хотя бы одно демонстрационное напоминание;
- профиль с базовыми учебными предпочтениями.

### После MVP, если останется время

- сравнение двух олимпиад;
- умный подбор по профилю;
- импорт/обновление расписаний по внешним источникам;
- push-напоминания для всех этапов.

Не заявлять, что даты обновляются автоматически, пока не реализованы импорт, проверка источников и расписание обновления.

## Реализовано 22 сентября 2026

Созданы `apps/api`, `packages/contracts`, PostgreSQL-схема Drizzle и миграции. Комплектный CSV от 24.09.2026 содержит 640 олимпиад и 34 предмета. Импорт без аргументов обновляет полный состав каталога, сохраняя старые записи в личных планах. Карточки показывают текст расписания и уровень с пометкой проекта перечня, если она указана в источнике. API поддерживает поиск, фильтры, подробную карточку и личный план с заметками/переключателем отслеживания. Есть серверная проверка подписи MAX, JWT и локальный демонстрационный вход.

Календарь CSV сохранён без назначения неизвестного года. Текстовые этапы не считаются проверенными; ближайшие события вычисляются только после отдельной загрузки подтверждённых дат. Поскольку точное время в данных отсутствует, этапы используют `beginsOn`/`endsOn` (день) вместо выдуманных `beginsAt`/`endsAt` (момент времени). Проверенные даты становятся `needs_review`, если новая выгрузка меняет исходное расписание.

Реализован интерфейс `apps/web` на выбранном стеке: нижняя навигация, Каталог, План, Профиль, Данные и конфиденциальность, Помощь и FAQ. Общие компоненты и дизайн-токены находятся в `packages/ui`. Каталог, карточка олимпиады, план, заметки и отслеживание работают через существующий API; ответы проверяются общими Zod-контрактами. React Router отвечает за маршруты, TanStack Query — за серверные данные, Zustand — только за выбор олимпиад для сравнения.

Профиль предпочтений пока локальный, с явным указанием этого в интерфейсе. Отдельный демонстрационный режим `VITE_DATA_MODE=mock` использует шесть реальных публичных карточек и локальный план, без выдуманных дат и без автоматического переключения на моки при ошибке API. Бот-напоминания, синхронизация профиля, удаление аккаунта и автоматическое обновление источников пока не реализованы. Вкладка «Бот» на этом этапе была заглушкой; 23 сентября она заменена чатом «Олимп» (см. обновление ниже). Исходный CSV оставлен в корне без изменений. Запуск описан в `README.md`, фронтенд — в `docs/FRONTEND.md`, контракт API — в `docs/API.md`, модель данных — в `docs/DATA_MODEL.md`.

## Обновление 23 сентября 2026: Олимп

Новые ответы показываются с эффектом печати, карточки появляются по очереди. Поисковый вопрос формулируется по контексту; прямая просьба поискать показывает компактное подтверждение «Да / Нет», без пересказа базы. Шапка чата использует пользовательский логотип `apps/web/src/assets/olimp/logo.jpg`. При нехватке данных бот предлагает поиск в интернете через Serper с приоритетом сайтов организаторов. Проверка запускается только после согласия, возвращает реальные источники и предупреждение о самостоятельной проверке; подтверждённые даты базы не изменяет. Нужен серверный `SERPER_API_KEY`. Сервер ищет через Serper, затем читает до трёх результатов; для недоступных страниц/PDF допускается только явно помеченная выдержка из поиска. Старый обход связанных ссылок заменён Serper.

Вместо заглушки «Бот» реализован чат «Олимп» по Figma 177:309. Маршрут `/olimp`, `/bot` перенаправляется на него. DeepSeek вызывается только сервером через `/assistant/chat` после авторизации. Ассистент читает текущий PostgreSQL-каталог и личный план; карточки и ссылки берутся из базы. Из чата можно открыть подробности и добавить олимпиаду кнопкой «В план». Модель сама план не изменяет. Подтверждённые сроки берутся только из проверенных этапов; даты CSV без года не передаются как актуальные. Переписка живёт в памяти приложения, очищается при перезагрузке. Рассылка напоминаний по-прежнему не реализована. Настройки, границы и проверки — `docs/ASSISTANT.md`.

## Обновление 24 сентября 2026: вход и регистрация

Добавлены экраны `/welcome`, `/login`, `/register` по Figma «Добро пожаловать», «Вход», «Регистрация», с оригинальной иллюстрацией. Вход использует проверенную сервером личность MAX без отдельного логина и пароля. Регистрация — первичное заполнение профиля; повторный вход восстанавливает тот же профиль и план. После выхода личные экраны закрыты, кэш, токен и переписка очищаются.

Расширена существующая PostgreSQL: `user_profiles` хранит учебный профиль и отметку завершения регистрации, `user_subjects` связывает пользователя с предметами, `plan_items` сохраняет связь пользователя с олимпиадой. API: `GET /me`, `POST /me/registration`, `PATCH /me/profile`. Миграция сохраняет существующие UUID и планы. Имя, класс, город, предметы и форматы теперь синхронизируются через сервер; фото остаётся на устройстве. Старые локальные предпочтения можно перенести из страницы профиля.

Подробности и локальные режимы — `docs/AUTH.md`. Удаление серверного аккаунта и бот-напоминания всё ещё не реализованы. Для реального MAX необходимы токен бота на сервере и подключённый HTTPS URL; запуск внутри мессенджера требует отдельной проверки.
