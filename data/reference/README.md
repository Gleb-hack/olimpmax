# Справочник олимпиад: уровни, этапы, льготы вузов

Эта папка дополняет выгрузку olimpiada.ru (`data/catalog/olimpiady.csv`) данными, которых в ней нет или которые там неполны:

- **уровень** каждой предметной олимпиады по перечню РСОШ;
- **этапы и даты** из проверенного списка `olympiads_clean`;
- **льготы вузов** (БВИ, 100 баллов) и минимальный балл ЕГЭ для их подтверждения;
- **58 карточек**, которых не было в выгрузке olimpiada.ru (Олимпиада СПбГУ, олимпиады КФУ, Всесибирская и др.).

Всё здесь — обычные CSV. Их можно править в Excel/LibreOffice (кодировка UTF-8, разделитель `;` у собственных файлов проекта). База данных пересобирается из этих файлов целиком, поэтому **правьте файлы, а не таблицы в PostgreSQL**.

## Главная идея: серия

В каталоге олимпиады разделены по предметам («Олимпиада РАНХиГС по истории», «…по экономике»), а в источниках чаще встречается олимпиада целиком («Олимпиада РАНХиГС»). Серия связывает одно с другим:

```
series.csv            ranepa = «Олимпиада РАНХиГС» + псевдонимы из всех источников
catalog-links.csv     5285 → ranepa, профиль «история»;  5412 → ranepa, профиль «экономика»; …
```

Этапы, общий уровень и льготы хранятся у серии и автоматически применяются ко всем её карточкам. Уровень РСОШ — у профиля, поэтому у каждой карточки свой.

## Правила, по которым собираются данные

**Уровень карточки** (реализация: `apps/api/src/reference/levels.ts`):

1. Серия есть в перечне РСОШ → уровень профиля карточки из `olympiads_2026_2027`. Если у карточки несколько профилей — диапазон (`II–III`). Если профиль карточки в перечень не входит — уровня нет («Профиль не входит в перечень РСОШ 2026/27»), даже если у других профилей серии он есть.
2. Иначе — уровень из самой выгрузки olimpiada.ru (он тоже сопоставлялся с перечнем, но охватывает олимпиады, которых нет в файле перечня), включая её вывод «профиль не найден в перечне».
3. Иначе — общий уровень серии из `olympiads_clean`.

Почему не «общий уровень для всех предметов»: в перечне уровень задаётся по профилю. Например, у РАНХиГС история — II, экономика — III, а общий уровень в `olympiads_clean` — III. От уровня профиля зависят льготы.

**Расписание карточки** (реализация: `model.ts`, `features/catalog.ts`):

- Основное — этапы серии из `olympiads_clean`.
- Карточка показывает расписание olimpiada.ru, если:
  - расписание серии похоже на **шаблон**: регистрация «до X», отбор «до X+20», финал «X+50…52», или те же даты, что у другой олимпиады. Так выглядят 26 строк текущего `olympiads_clean`;
  - все даты серии с явным годом относятся к **прошлому сезону** (Звезда, РГГУ, СПб астрономическая — даты 2025/26);
  - у самой карточки на olimpiada.ru опубликовано расписание, и оно **не совпадает ни в одной дате** с расписанием серии. Так бывает, когда у предметов разные даты (Всесибирская: математика ≠ химия) или в `olympiads_clean` прошлогодние данные.
- Данные `olympiads_clean` при этом не теряются: они есть в API (`stages` с `origin: "reference"`), а карточка объясняет, почему они не показаны.
- Год к датам без года не добавляется. Даты справочника никогда не становятся «подтверждёнными» и не создают напоминаний: для этого по-прежнему нужен `pnpm db:stages` с источником и датой проверки.

**Льготы** могут приходить несколькими файлами: `benefits` в `manifest.json` — список источников; при совпадении вуза, олимпиады и льготы остаётся первая строка. Источник с `"skipUnknownOlympiads": true` пропускает олимпиады, которых нет в базе проекта, с предупреждением `skipped_olympiad` (так подключён файл 2026 года), остальные источники считают неизвестное название ошибкой. «БВИ / 100 баллов» — две льготы, «Не требуется» — подтверждать баллами ЕГЭ не нужно (дипломы ВсОШ).

Льготы хранятся у серии и показываются на карточке, только если у карточки есть уровень. Если профиль не входит в перечень, карточка пишет, что льготы серии на неё не распространяются. «БВИ» и «100 баллов» считаются льготой для победителей и призёров, «БВИ победителям» — только для победителей. Условие «ЕГЭ от75 до 85 баллов» превращается в диапазон 75–85 (порог зависит от программы). Пометка «не видно на предоставленных скриншотах» означает «порог не указан» и пользователю так и показывается.

## Направления и программы вузов

- **`directions.csv`** — справочник направлений бакалавриата (`XX.03.XX`) и специалитета (`XX.05.XX`): `code;name;education_level;ugsn_code;ugsn_name;ege_subjects;subjects_core;subjects_related;popular;aliases;note`. Предметы — через `|`. `ege_subjects` — только предметы ЕГЭ (Математика, Информатика, Физика, Химия, Биология, Обществознание, История, Литература, География, Иностранный язык, Русский язык); `subjects_core` и `subjects_related` — предметы каталога (как в поле «Предмет» `olimpiady.csv`). `data:check` проверяет, что код совпадает с уровнем и группой, коды не повторяются, а предметы есть в каталоге. Соответствие «предмет → направление» — типичное для большинства вузов, поэтому в интерфейсе это **рекомендация**.
- **`sources/university_programs.csv`** (источник `programs` в `manifest.json`) — программы вузов: `university_slug;direction_code;direction_name;education_level;program;faculty;exams_required;exams_choice;internal_exam;passing_score;passing_score_form;passing_year;funding;source_url;tabiturient_id`. `exams_choice` — группы экзаменов на выбор через `;`, внутри группы через `|`. `funding`: `budget`, `paid_only`, `quota_only`. Вуз должен быть в `universities.csv`, код — в `directions.csv`. Проходные баллы — кампании 2025 года по данным [Табитуриента](https://tabiturient.ru); Иннополиса там нет, его программы взяты с сайта приёмной комиссии.

Связь олимпиады с направлением (`olympiad_directions`) вычисляется при импорте:

1. **По перечню РСОШ** (`via_rsosh`): у профиля в перечне есть список «соответствующих направлений подготовки» — смесь предметов, укрупнённых групп и отдельных направлений. Направление подходит, если в этом списке целиком стоит название его группы («информатика и вычислительная техника») или его собственное название. Учитываются только профили, которые покрывает карточка (`catalog-links.csv`).
2. **По предметам** (`subject_relevance`): предмет карточки входит в `subjects_core` (`core`) или `subjects_related` (`related`) направления. Связующий предмет сохраняется в `olympiad_directions.subject`.

   olimpiada.ru ставит карточке все предметы, которых касаются задания: у «Высшей пробы» по финансовой грамотности это математика и экономика. Перечень РСОШ называет настоящие: «финансовая грамотность» → «экономика». Поэтому если у карточки **несколько** предметов, а её профиль в перечне называет часть из них **целым пунктом** («экономика», но не группа «экономика и управление»), профильными считаются только названные. Остальные теги дают не больше `related`. Профили считаются по отдельности, так что у НТО профиль без названных предметов сохраняет все теги. Единственный предмет карточки — её тема и не понижается, даже если перечень называет экзамен («право» → «обществознание») (`profileSubjects` в `apps/api/src/reference/directions.ts`).

**Сортировка по цели** (`sort=goal`, `apps/api/src/features/goal-match.ts`): льгота в целевом вузе считается, только если олимпиада ведёт в этот вуз. Нужно, чтобы у вуза была программа по направлению, к которому олимпиада подходит по перечню РСОШ или профильному предмету. Если в цели указаны направления — по одному из них. Если для вуза и серии есть строки правил приёма (`directionBenefits`) — по одному из направлений из этих правил. Иначе «БВИ в ИТМО» за «Высшую пробу» по дизайну засчитывалась бы ученику, который идёт на программную инженерию. Веса: льгота — 6 баллов за вуз (до трёх), перечень РСОШ и профильный предмет — по 4 за направление, близкий профиль — 1. Ещё +1 за направление, если связующий профильный предмет стоит **первым** в `subjects_core` (главный предмет: «Информатика» у программной инженерии, «Математика» у ПМИ), поэтому порядок предметов в `subjects_core` важен (он хранится в `direction_subjects.position`). Уровень добавляется один раз: ВсОШ 4, I 3, II 2, III 1, вне перечня 0.

**«На N из M направлений».** Для каждой пары «вуз × олимпиада» считается, на сколько направлений вуза помогает диплом. Точно — если есть строки из правил приёма (ниже); иначе оценка: сколько направлений вуза имеют программу с экзаменом, за который засчитывается диплом (`directionCoverage` в `apps/api/src/reference/directions.ts`).

**Точные льготы по направлениям** (необязательно): файлы в `sources/`, перечисленные в `manifest.json` как `"directionBenefits": [{ "file": "sources/…csv", "description": "…" }]`. Формат: `university_slug;olympiad;direction_code;benefit;source_url;source_page`. `olympiad` — название серии или любой её псевдоним из `series.csv`, `benefit` — как в файлах льгот (`БВИ`, `100 баллов`, `БВИ / 100 баллов`, `БВИ победителям`), `source_url` — ссылка на правила приёма или приложение к ним (обязательна), `source_page` — страница PDF. Достаточно заполнить вузы, по которым есть документ: для остальных останется оценка.

Программа подходит олимпиаде, если вуз даёт льготу по её серии, направление программы подходит олимпиаде по перечню или основному предмету, а при `examMatch` в экзаменах программы есть предмет диплома (правила — `apps/api/src/reference/directions.ts`).

## Как обновлять

После любой правки:

```bash
pnpm data:check      # проверка без базы: ошибки, предупреждения, отчёт data/reference-report.json
pnpm db:reference    # загрузить справочник в PostgreSQL (каталог не трогается)
# или полностью, вместе с каталогом:
pnpm db:import
```

`data:check` завершается с ошибкой, если что-то не сходится, а `db:reference` / `db:import` в этом случае ничего не меняют в базе: всё загружается одной транзакцией.

### Пришла новая версия `olympiads_clean`, перечня или льгот

1. Положите файл в `sources/` (под тем же именем или поправьте путь в `manifest.json`).
2. `pnpm data:check`. Если олимпиада называется по-новому, будет ошибка `unknown_olympiad: … не найдена в series.csv` — допишите это название в `aliases` нужной серии (варианты через `|`) или добавьте новую серию.
3. Новый сезон перечня: поменяйте в `manifest.json` `season`, `status` (например, «Перечень РСОШ 2027/28») и `url`. Когда перечень утверждён, уберите из `status` слово «проект».
4. `pnpm db:reference`.

Формат источников проверяется по заголовкам столбцов; разделитель (`,` или `;`) определяется автоматически. В `olympiads_clean` может быть сколько угодно этапов: `этап_N`, `дата_N`, `формат_N`.

### Добавить олимпиаду или её предмет

- Новая серия: строка в `series.csv`. `slug` — латиница, цифры, дефис; меняйте его только вместе со ссылками в `catalog-links.csv`. `catalog_group` — название «Объединения» на olimpiada.ru (поле «Источник» в `olimpiady.csv` без приставки «Объединение: »). По нему `data:check` предупреждает о карточках из этого объединения, которые ещё не привязаны. Карточки объединения, которые к серии не относятся, перечислите в `catalog_exclude` через `|`.
- Новая карточка серии: строка в `catalog-links.csv` — `olympiad_id;series;profiles;title_hint;note`. `profiles` — точные названия профилей из перечня через `|`, `*` — все профили серии, пусто — профиль в перечень не входит. `title_hint` нужен только человеку.
- Карточки нет в выгрузке olimpiada.ru: добавьте строку в `catalog-additions.csv` в формате `olimpiady.csv`, ID и URL — со страницы olimpiada.ru. Когда карточка появится в новой выгрузке, будет использована версия из выгрузки (отчёт импорта покажет `additionsSuperseded`), а строку из additions можно удалить.

### Даты серии проверены вручную

Если расписание помечено как шаблонное или прошлогоднее, но вы проверили его у организатора, поставьте в `series.csv` `schedule_review = ok`. Чтобы, наоборот, никогда не показывать даты серии, поставьте `hide`. Пустое значение — автоматическая проверка.

### Новый вуз

Строка в `universities.csv`. Все варианты написания вуза в файле льгот — в `aliases` через `|`. Программы вуза — строки в `sources/university_programs.csv` с его `slug`; без них `data:check` предупредит `university_without_programs`.

### Новое направление или программа

Направление — строка в `directions.csv` (код и название по перечню Минобрнауки). Программа с кодом, которого нет в справочнике, — ошибка `unknown_direction`: сначала добавьте направление.

## Отчёт `data/reference-report.json`

- `counts` — сколько серий, профилей, льгот, связей;
- `schedule` — какие серии показывают свои даты, какие признаны шаблоном или прошлогодними;
- `scheduleConflicts` — карточки, у которых своё расписание olimpiada.ru противоречит расписанию серии;
- `scheduleComparison` — для каждой серии с «доверенным» расписанием: даты `olympiads_clean` рядом с датами olimpiada.ru одной из карточек. Это удобно для ручной сверки;
- `levelChanges` — у каких карточек уровень отличается от прежнего значения в выгрузке и почему;
- `warnings` — например, профиль перечня, для которого в каталоге нет карточки.
