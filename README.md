# Olimp — Mini App, база олимпиад и API

Mini App в MAX с каталогом и личным планом. Стек из `PROJECT_BRIEF.md`: **React + TypeScript + Vite + MAX UI** на клиенте, **PostgreSQL 16 + Drizzle + Fastify + Zod** на сервере, pnpm workspace.

Исходный `olimpiady.csv` сохранён без изменений. После импорта приложение читает PostgreSQL, а не CSV.

**Публичный запуск и подключение к MAX:** [пошаговая инструкция](docs/DEPLOYMENT.md). Готовы `Dockerfile`, `compose.production.yaml` и HTTPS через Caddy. Секреты задаются на сервере в `.env.production`.

## Что работает

- Каталог: поиск по названию, предметам, организатору и описанию; фильтры по предметам, классам, формату, типу участия и наличию расписания; сортировка и пагинация.
- Подробная карточка: все исходные поля, описание, организаторы, контакты, названия документов, особенности, календарь и ссылка на источник.
- Личный план: добавить, удалить, приостановить отслеживание, сохранить заметку; данные разных пользователей разделены.
- **Олимп**: чат с DeepSeek по каталогу, подбор по предмету и классу, сведения и подтверждённые сроки. Ответы печатаются постепенно, карточки появляются по очереди. Если данных не хватает, бот с согласия пользователя ищет в интернете через Serper и проверяет найденные источники, показывает источники и предупреждение о проверке информации.
- Ближайшие начала и окончания этапов с подтверждёнными датами. Учитываются текущий день и московский часовой пояс.
- Вход через проверку подписи MAX и часовой JWT. Для локальной разработки есть отдельный демонстрационный пользователь.
- Повторяемый импорт: обновляет записи, не создаёт дубликаты и сохраняет планы пользователей.

Интерфейс реализован по макетам Figma: нижнее меню, **Каталог**, **Мой план**, **Профиль**, **Данные и конфиденциальность**, **Помощь и FAQ**. Каталог и план подключены к API. Работают поиск, фильтры, сортировка, сравнение двух олимпиад, подробная карточка, сохранение в план, заметки и отслеживание. Добавлены экраны приветствия, входа и регистрации через MAX. Учебные предпочтения и план сохраняются в аккаунте на сервере; фото остаётся на устройстве. Подробности: [docs/AUTH.md](docs/AUTH.md).

**Рассылка ботом, удаление серверного аккаунта и автоматическое обновление расписаний пока не реализованы.** Соответствующие ограничения явно обозначены в интерфейсе. Подробности: [docs/FRONTEND.md](docs/FRONTEND.md).

## Данные и даты

Чат доступен во вкладке **Олимп** (`/olimp`, старый `/bot` перенаправляет туда). В корневом `.env` задайте серверные `DEEPSEEK_API_KEY` и `SERPER_API_KEY` (поиск в интернете); модель по умолчанию — `deepseek-flash`, настройка `DEEPSEEK_MODEL`. После изменения переменных перезапустите API. Ключ нельзя помещать в `VITE_*`. Чат требует входа через MAX или локального `/auth/dev`, в mock-режиме отключён. Подробности и ограничения: [docs/ASSISTANT.md](docs/ASSISTANT.md).

| Показатель | Значение |
| --- | ---: |
| Олимпиады | 771 |
| Отдельные предметы | 35 |
| Есть текст расписания | 210 |
| Расписание неизвестно | 430 |
| Указано «не проводится» | 131 |
| Выделенные текстовые этапы | 501 |
| Нет описания | 296 |
| Нет диапазона классов | 9 |
| Даты, подтверждённые при импорте CSV | 0 |

CSV содержит даты вроде «До 1 ноя», без надёжно установленного года. Они сохранены в `calendarRaw` и `stages[].rawDates`; год им не присваивается. В исходной базе `nextEvent = null`. Это означает отсутствие подтверждённой даты, а не отсутствие олимпиады или возможности сохранить её в план.

Проверенные даты загружаются отдельно с полным годом, ссылкой на источник, временем проверки и именем проверившего. Если после нового CSV изменились календарь, статус или отметка обновления, проверенные этапы получают `needs_review` и перестают участвовать в расчёте ближайших событий до повторной проверки.

Даты здесь имеют точность **до дня** (`beginsOn`, `endsOn`). Точное время не выдумывается. Отправка уведомлений в определённый час потребует отдельного правила и реализации бота.

## Быстрый старт

Нужны Node.js 22+ и pnpm 11.25.0. Команды запускаются из корня проекта.

```bash
pnpm install --frozen-lockfile
```

На текущем компьютере уже созданы `.env` и локальная база в `.local/postgres`. API использует порт **3001**, PostgreSQL — **55432**. Для повторного запуска:

```bash
pnpm db:local start
pnpm db:migrate
pnpm dev
```

`pnpm dev` запускает API на **3001** и Mini App на **5173**. Откройте [Olimp](http://127.0.0.1:5173). По отдельности: `pnpm dev:api` и `pnpm dev:web`. API каталога доступен без входа; интерфейс открывается после входа или регистрации. Вне MAX на локальном dev-сервере используется `/auth/dev` при `ALLOW_DEV_AUTH=true`. Этот вход отсутствует в production-сборке клиента.

`db:local` использует установленный PostgreSQL 16; при другом расположении задайте `PG_BIN`. Остановить базу: `pnpm db:local stop`. Каталог в ней уже загружен; повторный `pnpm db:import` безопасен для планов.

### На другом компьютере

1. Скопируйте `.env.example` в `.env`.
2. Задайте собственный `JWT_SECRET` длиной не менее 32 символов. Например, сгенерируйте: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
3. Для локальной демонстрации поставьте `ALLOW_DEV_AUTH=true`. Для MAX укажите серверный `MAX_BOT_TOKEN`, оставив `ALLOW_DEV_AUTH=false`.
4. Запустите PostgreSQL: `docker compose up -d` **или** `pnpm db:local start`. Не запускайте оба варианта на одном порту.
5. Выполните команды:

```bash
pnpm db:migrate
pnpm db:import
pnpm dev
```

Для своего PostgreSQL задайте `DATABASE_URL`. При смене пароля также обновите `POSTGRES_PASSWORD`. Локальный помощник обслуживает только `olimp@127.0.0.1:55432/olimp`.

Проверка: [состояние API](http://127.0.0.1:3001/health), [каталог](http://127.0.0.1:3001/olympiads), [фильтры](http://127.0.0.1:3001/olympiads/filters), [карточка № 88](http://127.0.0.1:3001/olympiads/88).

## Импорт и обновление

```bash
pnpm db:audit
pnpm db:import
# Или импорт новой выгрузки с теми же 19 столбцами:
pnpm db:import /absolute/path/olimpiady.csv
```

Импорт сначала проверяет весь файл, затем выполняется в одной транзакции. Неверная строка отменяет импорт с сообщением об ошибке. Ключ записи — ID страницы olimpiada.ru. Исходные поля сохраняются в `rawSource` без потерь, а нормализованные значения используются для фильтров.

Записи, которых нет в новой выгрузке, **не удаляются**: выгрузка может быть частичной. Их ID попадают в `missingFromFile` отчёта. Удаление и архивирование отсутствующих записей — отдельное решение. Предыдущие импорты зарегистрированы в таблице `import_runs`.

Отчёты: [data/source-audit.json](data/source-audit.json), [data/import-report.json](data/import-report.json).

### Перенос базы

Для новой установки используйте `db:migrate` и `db:import`. Локальные SQL-снимки и резервные копии не публикуются в Git; миграции создают актуальную схему, исходный CSV восстанавливает каталог. Перенос существующих пользователей и планов выполняется отдельно через защищённую резервную копию PostgreSQL.

## Подтверждённые этапы

Подготовьте JSON по [инструкции](docs/DATA_MODEL.md#проверенные-даты) после проверки официального расписания и выполните:

```bash
pnpm db:stages /absolute/path/verified-stages.json
```

Команда сохраняет результат проверки, **сама сайт не проверяет**. Импортировать проверенные этапы может оператор с доступом к базе; публичного endpoint для присвоения датам статуса «проверено» нет. Тестовые даты находятся только в тестах и не попадают в рабочую базу.

## Проверки и сборка

```bash
pnpm typecheck
pnpm test
pnpm test:integration
pnpm build
pnpm start
```

Интеграционные тесты создают отдельную базу `olimp_test_<случайный ID>`, применяют настоящие миграции, импортируют полный CSV и удаляют только свою временную базу. Пользователю PostgreSQL для тестов требуется право `CREATEDB`. Тесты не очищают рабочий каталог и личные планы.

## Перед подключением к MAX

Нужны токен бота, HTTPS-размещение API, разрешённый адрес фронтенда в `CORS_ORIGIN`, `NODE_ENV=production`, сильный `JWT_SECRET` и `ALLOW_DEV_AUTH=false`. Токены хранятся только на сервере. После разработки создание/изменение схемы и работа API могут использовать разные PostgreSQL-роли; расширение `pg_trgm` устанавливается миграцией и должно быть разрешено администратором БД.

Подпись проверяется по [официальному алгоритму MAX](https://dev.max.ru/docs/webapps/validation). Автоматические тесты проверяют HMAC и границы срока действия; вход с реальным токеном бота в этой сессии не проверялся.

Данные получены из [olimpiada.ru](https://olimpiada.ru/). Ссылка `sourceUrl` доступна на подробной странице олимпиады; подпись источника убрана из карточек каталога. Контакты с `...` и названия документов без URL нельзя автоматически превращать в ссылки. Регион, курс студента, льготы и уровень РСОШ как отдельные надёжные поля в этой выгрузке отсутствуют.
