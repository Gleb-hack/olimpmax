# Работа с проектом

Настройте окружение по [README](README.md#быстрый-старт). Рабочая основа — `main`; изменения оформляйте отдельной веткой и pull request.

## Куда вносить изменения

- Интерфейс и страницы — `apps/web`; общие компоненты — `packages/ui`.
- API и работа с базой — `apps/api`; бот — `apps/bot`.
- Общие форматы запросов и ответов — `packages/contracts`.
- Исходные наборы — `data`; инструкции — `docs`.
- Серверные тесты — `tests`; клиентские — `apps/web/test`.

Не редактируйте уже применённые SQL-миграции: после изменения схемы создайте новую через `pnpm db:generate` и проверьте её на локальной базе. При переносе файлов обновляйте ссылки, тесты и пути импорта.

## Перед pull request

```bash
pnpm check
pnpm test:integration
```

Для интеграционных тестов нужна отдельная локальная PostgreSQL или база из `compose.yaml` с правом `CREATEDB`. Не используйте для разработки production-окружение.

В описании укажите, что изменилось, как это проверить и какие проверки выполнены. Изменения интерфейса дополните скриншотом. Если меняется запуск, API или структура данных, обновите соответствующую инструкцию.

Не коммитьте `.env`, токены, дампы базы, `node_modules`, сборки и сгенерированные отчёты. Примеры настроек находятся в `.env.example` и `.env.production.example`. Состав зависимостей фиксируется в `pnpm-lock.yaml`; используйте указанную в `package.json` версию pnpm.
